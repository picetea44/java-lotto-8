# java-lotto-precourse
## 기능 목록

### 1) 구입 금액 입력
- [x] "구입금액을 입력해 주세요." 문구를 출력
- [x] 사용자가 구입 금액을 입력
- [x] 예외 (재입력 처리)
    - [x] 빈 문자열
    - [x] 양의 정수가 아닌 경우
    - [x] 1000원으로 나누어 떨어지지 않는 경우

### 2) 로또 발행
- [x] 구입 금액을 1000으로 나눈 **몫**만큼 로또를 발행
- [x] 각 로또는 1~45 범위의 서로 다른 숫자 6개로 구성
- [x] 발행된 각 로또 번호는 오름차순으로 정렬
- [x] "N개를 구매했습니다."를 출력
- [x] 발행된 로또들을 각 줄에 `[n1, n2, n3, n4, n5, n6]` 형식으로 출력

### 3) 당첨 번호 입력
- [x] "당첨 번호를 입력해 주세요." 문구를 출력
- [x] `1,2,3,4,5,6` 형식으로 정확히 6개 번호를 입력
- [x] 예외 (재입력 처리)
    - [x] 빈 문자열
    - [x] ',' 구분자로 분리한 숫자가 6개가 아닌 경우
    - [x] 양의 정수가 아닌 경우
    - [x] 1~45 범위를 벗어난 경우
    - [x] 중복된 숫자가 발생한 경우

### 4) 보너스 번호 입력
- [x] "보너스 번호를 입력해 주세요." 문구를 출력
- [x] 보너스 번호 1개를 입력
- [x] 예외 (재입력 처리)
    - [x] 빈 문자열
    - [x] 양의 정수가 아닌 경우
    - [x] 1~45 범위를 벗어난 경우
    - [x] 당청 번호와 중복된 경우

### 5) 채점(등수 판정)
- [x] 사용자가 가진 각 로또에 대해 당첨 번호 일치 개수를 계산
- [x] 5개가 일치할 경우 보너스 번호 일치 여부를 판단
- [x] 일치 수/보너스 여부에 따라 등수를 판정
    - [x] 6개 일치 → **1등 (2,000,000,000원)**
    - [x] 5개 + 보너스 일치 → **2등 (30,000,000원)**
    - [x] 5개 일치 → **3등 (1,500,000원)**
    - [x] 4개 일치 → **4등 (50,000원)**
    - [x] 3개 일치 → **5등 (5,000원)**
    - [x] 그 외 → 낙첨

### 6) 당첨 통계 출력
- [x] 아래 형식의 헤더를 출력
    - [x] `당첨 통계`
    - [x] `---`
- [x] 등수별로 `X개` 형식의 **개수**를 출력
    - [x] `3개 일치 (5,000원) - X개`
    - [x] `4개 일치 (50,000원) - X개`
    - [x] `5개 일치 (1,500,000원) - X개`
    - [x] `5개 일치, 보너스 볼 일치 (30,000,000원) - X개`
    - [x] `6개 일치 (2,000,000,000원) - X개`

### 7) 수익률 계산/출력
- [x] 총 당첨 금액을 계산(등수별 상금 × 개수의 합)
- [x] 수익률 = (총 당첨 금액 / 총 구입 금액) × 100 을 계산
- [x] 수익률을 소수 둘째 자리에서 반올림해서 소수 첫쨰짜리까지 출력
  예) `총 수익률은 62.5%입니다.`

### 8) 에러 처리 공통
- [x] 잘못된 입력에 대해 `[ERROR] ...` 형식의 메시지를 출력
- [x] 에러 발생 시 프로그램을 종료하지 않고 해당 단계부터 재입력

## 리팩토링 항목

### 1. Rank enum의 조건문 개선
- **문제점**: `of()` 메서드에 if문이 중첩되어 가독성 저하
- **개선**: Stream 기반으로 변경하고 `bonusRequired` 필드 추가로 각 등수별 규칙 명시화
- **효과**: 새로운 등수 추가 시 enum 상수만 추가하면 되도록 확장성 개선

### 2. 입출력 책임 분리
- **문제점**: Controller에 입출력 로직과 재시도 로직이 과도하게 집중
- **개선**: Input/Output 클래스로 io 패키지 구조화, 재시도 로직을 `Input.readWithRetry()`로 통합
- **효과**: Controller는 흐름 제어에만 집중, 입출력 로직의 중복 제거

### 3. 메서드 크기 제한 준수
- **문제점**: `LottoController.run()` 메서드가 과도한 책임을 가짐 
- **개선**: `issueAndPrintTickets()`, `printResult()` 메서드로 분리
- **효과**: 모든 메서드가 15라인 이하가 되어 단일 책임 원칙 준수

### 4. 출력 메시지 캡슐화
- **문제점**: 당첨 통계 출력 시 하드코딩된 메시지가 반복
- **개선**: Rank enum에 `getDescription()` 메서드 추가하여 서식 캡슐화
- **효과**: 출력 형식 변경 시 한 곳만 수정하면 되도록 유지보수성 향상
